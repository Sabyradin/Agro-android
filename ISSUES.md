# ISSUES.md — API ғажайыптары және ашық сұрақтар

Әр API мінез-құлығына күмән/спекке сай келмеушілік осында жазылады. Шешілгені — [x] + жауабы.

1. **[resolved — Фаза 11] google-services.json плейсхолдер схемасымен қосылды** — `app/src/dev/google-services.json` (com.agroland.app.dev) + `app/src/prod/google-services.json` (com.agroland.app). Нақты Firebase конфигурациясы (project_id, api_key, mobilesdk_app_id) команда бергенше осы файлдарға қойылады; код өзгерісі қажет емес. Плейсхолдер жағдайында FCM токені алынбайды → POST /device жіберілмейді, push мүлде үнсіз ыдырайды (Flutter setupFlutterNotifications try/catch үлгісі). `mobilesdk_app_id` форматы плагин талабына сай (1:N:android:hex).
2. **[open] `POST /auth/biometric` backend route.py-де тіркелмеген** (спек айтады) — биометриялық логин best-effort, 404 → биометриялық кіру түймесін жасыру.
3. **[open] Privacy/Terms нақты URL-дері** — сайт `/terms`, `/policy` жойған; команда бергенше конфигте `about/privacy/terms` markdown жолдары қолданылады (CommonMarkdownView, Фаза 18).
4. **[open] Dev тест-аккаунттар** (дилер 7001112203 + individual) — Фаза 3 эмуляторлық тексеріске керек.
5. **[open] «Менің пікірлерім»** эндпоинті жоқ — клиент жағында жиналатын болады (спек §10), BACKEND_REQUESTS.md-ге де жазылды.
6. **[open] DealerSupportSection (профиль хабі) әзірге іске қосылған жоқ** — Flutter-де дилер профиліндегі қолдау секциясы support-чатке ашылады (Socket.IO чатының жүйелік чаттары 31/1001–1005). Чат модулі Фаза 12-де қосылғанда осы жол ашылады.
7. **[open] `GET /verification/status` жауабының `documents[]` форматы** — әр құжаттың ішкі өрістері (id/url/status) спекте толық көрсетілмеген; қазір тек саны есептеледі, құжат тізімінің толық UI-ы backend жауабы нақтыланғанда толықтырылады.
8. **[open] `PATCH /user/profile` жауабының формасы** — спек «толық профиль қайтады» дейді, бірақ кейбір backend маршруттары `{success: true}` ғана қайтаруы мүмкін; ProfileRepository осы жағдайда profile null болса Failure.Parsing емес, profile-ды қайта GET жасайды (updateProfile* әдістерінің барлығы refresh() шақырады — қауіпсіз).
9. **[open] Деталь бетіндегі иелік статистикасы (views/calls/favorites/messages)** — Flutter иесі көреді; ағымдағы user id SessionController арқылы қолжетімді емес (TokenStore тек token сақтайды). Фаза 12 чатқа да user id керек — сол кезде SessionController-ге `currentUserId` қосылып, статистика жолы қосылады.
10. **[open] Деталь бетіндегі «Чат» түймесі** — Фаза 12-де Socket.IO чат модулімен бірге қосылады; қоңырау шалу қазір ACTION_DIAL арқылы нақты жұмыс істейді.
11. **[resolved — Фаза 7] `GET /announcements` country_id параметрі** — сүзгіге локация қосылды: FilterPage CatalogPickerDialog (country/region/district) арқылы `country_id`/`region_id`/`district_id` жіберіледі. Flutter лентасының ұсынылатын жолында міндетті `country_id=4` — қазір қолданушы сүзгісі ретінде жіберіліп жатыр (app-region countryId-ден автоматты міндетті жіберу Flutter-де deprecation хабаршысымен қорғалған); эмуляторлық тексерістен кейін ұсынылатын лентаға app-region енгізілуі мүмкін.
12. **[open] `POST /ai/ad-content` DEV-те жауап бермейді** — барлық `lang` кодтарында `{"success":false,"error":{"message":"An unexpected error occurred"}}` қайтарады (AI қызметі өшірулі сияқты). CreateAdPage AI-тобы кнопкасы Failure.Http оқиғасын snackbar-ға шығарады, қызмет қосылғанда автоматты жұмыс істейді.
13. **[open] `POST /demands` дене пішімі белгісіз** — спек JSON дейді, бірақ басқа жарнама жасау маршруттары multipart. MakeOfferViewModel dual-mode: алдымен JSON жібереді, Failure.Http 400–422 келсе ештеңе жасалмағаны анық (4xx) — multipart form ретінде қайта жібереді.
14. **[open] Өңдеу режиміндегі сурет сақтау өрісі** — `existing_images` (URL тізімі үтірмен) атауы болжамды; Flutter коды бұл машинада жоқ, backend OpenAPI-да нақты аты жоқ. Қате атау болса өңдеуде суреттер жоғалады — эмуляторлық тексерісте нақтыланады.
15. **[open] Bulk-upload файл part атауы** — `file` атауы болжамды (OpenAPI-да `/announcements/bulk-upload` schema көрсетілмеген). 400 келсе `file` → `excel_file`/`document` нұсқалары байқалады.
16. **[open] `delivery_zone_ids` қайталанатын part форматы** — backend тізікті (`delivery_zone_ids=1&delivery_zone_ids=2`) күтуі болжамды; JSON-массив (`[1,2]`) түрі де мүмкін. Бизнес-аккаунт тексерілінгенде нақтыланады.
17. **[open] Bulk шаблон `lang` параметрі** — `kk/ru/en/zh` тікелей жіберіледі (бөлек endpoint JSON ішінде `language` алғысымен); backend `kz/ch` мапингін қажет етсе — 400 келгенде түзетіледі (жәшік жоқ басқа endpoint-терден айырмашылығы мүмкін).
18. **[open] `GET /cities` DEV-те 404** — спектегі Country→Region→City тізбегінің соңғы буыны жоқ; curl арқылы тексерілді (`{"detail":"Not Found"}`). App-region орнату ағыны Country → Region-мен шектеледі, `app_region_city_id` := region id (Flutter-дің AppRegionModel.cityId үйлесімділігі үшін). `/cities` пайда болса District деңгейі қосылады.
19. **[open] MAPS_API_KEY бос плейсхолдер** — `gradle.properties` `MAPS_API_KEY` қасиеті команда бергенше бос; картаның Google плиткалары жүктелмейді. LocationSelectionPage ешқашан stub болмайды: карта орнына ақпарат карточкасы көрсетіледі, GPS + reverse geocode + каталог таңдауы толық жұмыс істейді. Кілт берілгенде GoogleMap автоматты қосылады (код өзгерісі қажет емес, manifestPlaceholders арқылы).
20. **[resolved — Фаза 7] `POST /user/location` дене пішіні** — Flutter `mobile-app/lib/location/domain/location_model.dart` (toMap) арқылы нақтыланды: `house/street/country/area/province/locality` (бос емесдері) + `country_id/region_id/district_id` + міндетті `latitude/longitude` (картадан таңдалмаса 0.0 — backend district_id-ды өздігінен турындатады, Location fix 3d78fa9). `PATCH /user/location/{id}` Flutter-де жоқ — өңдеу = POST жаңа + DELETE ескі (refreshStale үлгісі); `address_id` (Address кестесі) мен `user_location_id` (сілтеме жолы) айырмашылығы сақталды — DELETE/CreateAd user_location_id пайдаланады. Жауап оқу: LocationModel.fromJson пішіні (parseLocation). 3-тен асқан мекенжай ескісі өшіріледі (Flutter maxAddresses=3). Ескерту: біздің LocationSelectionPage картасы — Flutter-дің MapsPage-і өлі код (yandex_mapkit өшірілген), нақты Flutter ағыны — тізім + GPS; карта SPEC/MASTER_PLAN «Картамен таңдау» бабы бойынша қалды және кілт жоқ болса дәл Flutter мінез-құлқына ыдырайды (тізім + GPS + reverse geocode).
21. **[resolved — Фаза 9] Halyk ePay өрісі** — SPEC «invoice_url» дейді, нақты backend/Flutter жауабы `payment_url` (POST /payments/halyk/init → {payment_url, invoice_id, amount, currency, mock}); Flutter эталоны бойынша `payment_url` оқылады. `mock=true` DEV ортасында WebView-сіз тікелей нәтижше бетіне жүреді. BCC legacy 3D Secure (POST /payment/generate) — backend HTML форманы P_SIGN (HMAC-SHA1) өзі құрып қайтарады, клиент WebView-та көрсетеді (Фаза 10 әмиян толтыруға дайын).
22. **[resolved — Фаза 10] Әмиян маршруттары: /business/\* vs /dealer/\*** — SPEC «/dealer/* — /business/* атауларының legacy алиасы, target /business/* напрямую» дейді, ал Flutter эталоны `/dealer/balance`, `/dealer/balance/transactions`, `/dealer/withdraw` шақырады. DEV-те екеуі де бар екені тексерілді (curl: `/business/balance` 401, `/business/withdraw` 405 — маршрут бар; 404 емес). SPEC бойынша `/business/*` нұсқалары қолданылды. Шығару кезінде баланс сұраныс кезінде емес, admin мақұлдағанда ғана кемиді (backend ledger); клиент тек {amount, bank_details:{iban, bank_name, bik?, account?}} жібереді, минималды сома 5 000 ₸ клиент жағынан алдын-ала тексеріледі (backend шектеуімен сәйкес).
23. **[resolved — Фаза 11] Push payload routing эталоны** — Flutter push_notification_service._handlePayload дәйек тізбегі Android портта толық қайталанды (PushPayloadRouter): verification_approved/rejected → верификация; balance_credited/withdraw_approved/withdraw_rejected → әмиян; review_request+order_id → тапсырыс; order_id → тапсырыс; event=chat+sender_id → чат бөлмесі; announcement_id → жарнама; notification_id+notification_type → хабарламалар тізімі; fallback → тізім. Қайталау қорғаны — payload-тан сортталған кілттерден id + 500 мс cooldown (Flutter _generateIdFromPayload/_isDuplicateNotification). Бос FCM токен ЕШҚАШАН POST /device етілмейді (backend EMPTY_FIREBASE_TOKEN).
24. **[open — Фаза 12-ге] Push межелері: ChatRoom + Notifications** — PushPayloadRouter ChatRoom (event=chat+sender_id, sender_name, room_id/chat_id, is_system_chat) және Notifications (notification_id+notification_type → тип тізімі) межелерін құрады, бірақ бұл экрандар әлі жоқ — MainActivity оларды әзірге күтілуде ретінде өткізіп жібереді. Фаза 12 (чат + хабарламалар тізімі) қосылғанда навигацияға жалғанады. Бейдж (чат + хабарламалар оқылмағандарының қосындысы) да Фаза 12-ге — чат unread санын Socket.IO қосқаннан кейін жинаймыз.
