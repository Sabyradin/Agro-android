# Agroland iOS — Swift Native Rewrite Specification

**Agroland iOS** — Swift-native iOS rewrite of the Agroland Flutter marketplace app — a KK/RU/EN/ZH-language agricultural B2B/B2C classifieds + commerce + real-time chat + voice-calling platform over a FastAPI backend, with Halyk ePay payments, WebRTC calls, and dealer/business tooling.

- Total screens: **65**
- Total endpoints: **220**
- Feature modules: **23**
- Target: iPhone first (iOS 17+), SwiftUI-first with UIKit interop, full feature-parity

## Critical Porting Risks

- WebRTC 1:1 voice calls (flutter_webrtc → WebRTC iOS SDK) — no Apple equivalent, large API surface: RTCPeerConnection, getUserMedia(audio only), SDP/ICE handshake, ICE restart (iceRestart:true re-offer, offerer-only, one attempt max + 20s fallback), pending-ICE-candidate buffering until remote description set, AVAudioSession .playAndRoute + speaker override, TURN REST credential refresh (5min margin). HIGHEST RISK.

- Socket.IO real-time chat (socket_io_client → SocketIO-Client-Swift) — must match engine.io v3/v4 protocol, websocket-only transport, auth {Bearer token, language}, infinite reconnection, and ALL ~25 events (chat_message, join_chat, typing, mark_read, edit/delete, load_older, call:* family). Must rebuild dedup/merge logic (ChatRoomModel.mergeRooms, optimistic localId → server echo replacement, fuzzy location-echo matching, _renderedRoomId dedup for join_chat_success flapping, text-message queue flushed on reconnect).

- awesome_notifications has NO direct Apple equivalent — rebuild on UNUserNotificationCenter (UNMutableNotificationContent, UNNotificationCategory, rich media, action handlers, killed-state pending-action persistence + replay on launch). Second-highest effort. Foreground FCM → local notification display, deep-link routing via payload event matching, cooldown/dedup by notification id.

- CallKit integration for backgrounded voice calls — currently the app uses an in-app overlay only; iOS requires CallKit (CXProvider) for native incoming-call UI and PushKit/CallKit for backgrounded calls. Missed calls currently delivered via FCM push then replayed via deliver_pending_calls on socket connect.

- Halyk ePay invoice-link payment flow — OAuth2 client_credentials → POST /invoice → open invoice_url in ASWebAuthenticationSession (NOT raw WebView — iOS 26 requires ASWebAuthenticationSession for hosted card pages to get Safari 3DS + keychain autofill). Callback is server-side postLink webhook, app never receives it → poll GET /orders/{id} payment_status every 2s for 60s. Keep mock-mode short-circuit when secret empty.

- Legacy BCC 3D Secure balance top-up — HMAC-SHA1 P_SIGN over MAC data string with hex BCC_SECRET_KEY, reimplement with CryptoKit HMAC<Insecure.SHA1>; response is HTML form that must render in WKWebView. Form-urlencoded POST to 3dsecure.bcc.kz:5443.

- POST /auth/biometric endpoint is NOT registered in backend route.py — mobile client calls it but it likely 404s. Biometric login (biometric_token exchange) is probably broken server-side; treat as best-effort or have backend add the route before relying on it.

- HATEOAS MFA auth flow with server-issued task_id is bespoke — phone → POST /auth/login → parse 'links' for mfaSmsRequest/mfaSmsSubmit → GET /auth/mfa/{task_id} (send SMS) → POST /auth/mfa/{task_id} {sms_code} → POST /auth/login with task_id header → tokens. Signup mirrors this with user_type='dealer' (BUSINESS) requiring company_bin. Signup fallback code 666666; SMS exempt phones skip.

- google_mobile_ads on iOS → Google Mobile Ads iOS SDK + ATTrackingManager request for IDFA. Currently DISABLED at boot in app_bootstrap and production ad-unit IDs are placeholder XXXX — re-enable decision needed and real AdMob IDs required before ship.

- TikTok Business SDK — already iOS-native (Swift bridge in AppDelegate.swift) but HMAC-signing accessToken flow is iOS-specific (Android SDK has no secret). ATT prompt must be requested before init (currently deferred to SceneDelegate.sceneDidBecomeActive). SKAdNetwork in SDK.

- Message-type inference (infer_message_type.dart) must be ported 1:1 — backend often sends message_type='text' with URL in message field, client infers image/video/audio/file/location from URL extension/substring.

- CRLF URL sanitization (JsonHelpers.sanitizeUrl) is a backend bug workaround that must be preserved in Swift URL handling.

- Freezed + json_serializable codegen → hand-written Codable structs with CodingKeys snake_case renames + custom init(from:) defaults; many Optional (nullable) fields; backend returns untyped dicts (response_model only on handful of routes) — hand-map each endpoint.

- Riverpod StateNotifierProvider.autoDispose + AsyncValue<T> → SwiftUI @Observable view models + .task/.refreshable; autoDispose = view model lifetime tied to view; FutureProvider.family → parameterized async reads. hooks_riverpod useEffect/useMemoized/useState → SwiftUI .task/onAppear/@State.

- ~1088 ARB localization keys (kk/ru/en/zh) → SwiftUI String Catalog (.xcstrings); ICU plurals + placeholders translate directly but source of truth must stay in sync. CRITICAL locale mapping: kk→'kz', zh/cn→'ch' for backend names{} bridge.

- 80 SVG icons + OpenSans 12 ttf faces — SF Symbols replace slugs where possible but brand/domain SVGs (flags, telegram, whatsapp, kaspi, payment, category illustrations) must ship as real SVG/PNG assets; OpenSans all needed weights registered via Info.plist UIAppFonts.

- BigInteger (int64) for ChinaCartItem.product_id and sku_id — use Int64, not Int32.

- Base URL double-prefix /api/v1 gotcha — BaseRemoteRepository re-reads baseApiUrl AND concatenates full path, both contain /api/v1; Swift APIClient must standardize on one approach to avoid double-prefixing.

- Multi-supplier cart checkout requires client to pick a single supplier (SupplierPickerSheet) because Halyk init takes one order_id — preserve this constraint.

- Deep-link routing from killed-state push payload — pending action persisted in UserDefaults (replacing SharedPreferences) and replayed on launch (currently via _checkPendingNotificationActions).

- Force-update non-dismissable dialog + App Store link — replicate on launch + scenePhase .active; optional updates deduped by last-shown-version in UserDefaults.

- Pending Halyk payment resume on launch — read pending order id from UserDefaults → push payment-result polling screen.

- Background socket lifecycle — app background→foreground must call socket.connect()+REST refresh (ChatSocketService.onAppResumed equivalent); iOS will need similar lifecycle handling via scenePhase.

- Order fulfillment status (supplier_query→...→paid) is INDEPENDENT from payment_status (unpaid/paid/refunded) — do not conflate in UI; TRANSITIONS matrix must be reproduced or fetched.

- Legacy /dealer/* ↔ /business/* aliases (20260908000001 dealer→business rename) — wire-compat dealer_id still emitted alongside business_id in some responses; target /business/* paths in Swift, keep /dealer aliases for backward compatibility.

- Withdrawal flow debits balance ONLY at admin approval (not at request), with row-level locking — iOS withdraw form enforces min 5000 KZT client-side but balance check is server-side.

- Cron-based expiry of boost/vip/auto-renew lives on backend — Swift client only reads expires_at; do not reimplement client-side expiry logic.

## iOS Framework Recommendations

SwiftUI-first (iOS 17+) with UIKit/AppKit interop where SwiftUI is insufficient (WKWebView, AVPlayerViewController, CallKit, QR camera preview). Min iOS version 17 recommended — gives @Observable macro (replaces Riverpod StateNotifier+AsyncValue cleanly), mature NavigationStack with path-based routing + deep links, String Catalogs (.xcstrings) for the 4-locale ARB port, fullScreenCover for story viewers, TimelineView for story progress timers, and .task/.refreshable for async view-model binding. iOS 16 is possible but loses @Observable and String Catalogs, forcing Combine/CurrentValueSubject + .strings files. Given the app ships to Kazakhstan users on a range of devices, iOS 17 is a reasonable floor (90%+ adoption). Mix: UIKit where needed — WKWebView (WebKit) for CommonWebViewPage + YouTube IFrame API, AVPlayerViewController for video, PDFView (PDFKit) for PDFs, AVCaptureSession + VNDetectBarcodesRequest (Vision) for QR, CallKit (CXProvider) for voice calls, PHPickerViewController for image picking, UIDocumentPickerViewController for file picking, UIDocumentInteractionController/QLPreviewController for open-filex, UIActivityViewController for share, ASWebAuthenticationSession for Halyk ePay.
